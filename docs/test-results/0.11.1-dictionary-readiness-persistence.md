# 0.11.1 dictionary, translation readiness and safe persistence

Date: 2026-10-26. Branch: `codex/local-media-loopback`. Baseline committed
comparison: `0455ce3`; starting working candidate: 0.11.0.
WP1.3/WP2.4, WP3.5, WP0.3. Plan: `DICTIONARY_READINESS_PERSISTENCE_PLAN.md`.

**Result: Needs development.** Implementation and automated regression are
present; final dictionary acceptance has failures and real Chrome preparation
did not complete. This is a candidate, not a passing release.

## What changed

The parent made every code/test/documentation edit. Only manual source comparison
was delegated to built-in GPT-6 Luna, with no file-edit permission. No model,
embeddings, training, inference dependency or OpenAI key entered the extension.

- An inert HTML tree replaces cross-section extraction. German language and
  lexical sections bound definitions/examples/grammar/forms. Meaning IDs combine
  section and reference. Multiple/ranged references expand; examples without a
  reliable match stay section-level. No guessed relationships.
- Separate meanings and full examples survive normalization/storage. Compact
  presentation keeps expansion controls, including detailed conjugations. Source
  quotation marks are not doubled; recognized editor/role labels are separated.
- Case annotations preserve alternatives/conditions/qualifications. Section-wide
  rules receive no invented meaning number. Verb overview rows preserve person,
  tense/mood and alternatives; per-sense auxiliaries and explicit verb base-form
  references remain. Unavailable forms are never generated. Active source stays
  German Wiktionary only. Dictionary cache generation changes; old saved words
  remain readable, including the preexisting offline fallback.
- Readiness appears above Analyze and checks both selected languages on open and
  change. A dedicated setup tab's direct click calls Translator creation before
  a message hop. Progress uses normalized percentages, not invented byte totals.
  Creation success, not 100%, establishes Ready. Chrome manages resources.
- Bounded waits cover browser creation/translation and optional cloud requests.
  Late creation cannot mark an expired request Ready; existing revisions reject
  stale word/language results. Errors are not successful cache entries. Direct
  source-to-target routing, browser-first policy and provider-aware cache remain.
- Shared allowlisted projections run before vocabulary/experiment/library and
  nested diagnostic writes, and experiment exports. URLs lose credentials,
  query secrets and fragments; supported YouTube `v` identity remains. Opaque
  acquisition objects cannot become persistent records.
- Repeatable migration replaces affected records in place and writes its marker
  last. It never deletes whole records as cleanup. Optional translation keys stay
  in their existing separate configuration. Existing Netflix research collectors
  retain their prior explicitly sanitized metadata contracts.

## Persistence and remaining gates

Automated and browser migration fixtures use artificial credential/query,
authorization/PCM/key sentinels. Three affected browser records were cleaned;
counts, context, experiment ID, transcript cue/word timing, source link and
separately configured fake key survived. Storage/export contain none of the
supplied secrets. Repeating migration leaves results unchanged. Same-ID reload
from working 0.11.0 to 0.11.1 retains these records. Personal browser storage was
neither touched nor audited.

Unrelated manual platform playback, fullscreen/dragging, audible pronunciation,
real cache playback, Windows reinstall and full browser restart were not tested.
Missing evidence is not a pass. This remains a candidate needing development.
