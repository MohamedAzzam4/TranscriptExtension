## Implementation and preserved contracts

- Render source captions immediately after cache/network/native source retrieval,
  with current appearance settings. Optional translation and source persistence
  follow independently; storage quota/failure cannot hide usable source text.
- Update target captions in the existing session/overlay, guarded by video and
  request identity. Preserve displayed source, selection, card and hover state.
  While the YouTube target is pending, show Preparing translation in its line;
  then use aligned YouTube target or Chrome/configured Cloud fallback on failure.
  Cached source/target can still appear together immediately.
- Native helper source request omits target language. An optional second
  subtitle-only request obtains target afterward, bound to the same source
  track/language; this may repeat metadata/source retrieval, trading extra work
  for earlier source rendering. Existing18s browser/45s native bounds remain.
  No audio acquisition, ASR, helper executable or server implementation changes.
- Source saves first; later target data binds to the same saved entry. New
  overlay initially uses a transient request ID, replaced after save. Data schema,
  safe source identity, provenance and two-language cache policy remain intact.
- Player-level compact live status reports source/target preparation even before
  our caption session exists. Source stays usable while target prepares. Ready
  feedback fades after2seconds plus a300ms opacity transition; warnings remain
  actionable, and full status stays in popup/menu diagnostics. Ad state hides it.
  UI typography is isolated from the host page; reduced motion remains supported.
- youtube-playback.js owns one attempt per video visit after valid current-video
  metadata, ready media, visible tab and no ad. Already playing/ended media or
  observed user intent cancels the attempt. Settings/retry/media replacement
  retain attempt state. Navigation/disposal removes listeners and rejects stale
  reporting. Later user/hover pauses are never undone by polling.
- play() rejection shows press Play and a Playback diagnostic, without forced
  mute or retry loops. MDN play()/autoplay docs retrieved through Context7 confirm
  NotAllowedError can require a user gesture; guaranteed autoplay is not claimed.
  This applies to enabled YouTube caption mode, not generic sites/audio mode.

Creator-first/original-automatic priority, no implicit ASR, native-caption
restoration, settings, cached replay, save/card/YouGlish/replay/selection/drag and
generic embedded media remain protected. Content version29, manifest/popup0.12.4.
