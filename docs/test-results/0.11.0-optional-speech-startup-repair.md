# Optional speech startup and player-discovery repair

Date: 2026-10-25. Version 0.11.0 working-tree candidate, branch
`codex/local-media-loopback`, baseline commit `0455ce3` plus existing changes.
Parent implementation; no Terra delegation. WPs WP1.1 / WP0.3 / WP2.4.
Dependencies: content injection, helper loading, frame messaging, existing cache
selection and diagnostics. Protected contracts ACQ-GENERIC, TR-CACHE,
INT-WORD and optional browser pronunciation.

## Actual browser evidence

The user again reported `No accessible HTML video was found`. After the user
explicitly authorized read-only browser diagnosis and player-discovery
inspection without transcription/audio capture, the parent inspected the
existing Edge AniWorld tab through the computer/browser tools.

The page accessibility tree showed the embedded VOE player and its paused
timeline. DOM inspection confirmed no top-document video, with an embedded
player frame. Captured console errors from the extension in that tab included:

> Error: Browser pronunciation helpers were not loaded.

The exception occurred at content.js line 14 in multiple frames. This is a
different failure from the previously repaired syntax error. Missing optional
speech code aborted the entire player application before GET_MEDIA_CONTEXT
could register. Additionally, the content script published its version sentinel
before dependency validation, so an unsuccessful initialization could cause
later injections to return early permanently for that document.

An older running worker/incomplete update loading newer content without the
new helper is consistent with this trace, but the exact reason the helper was
absent was not proven. The repair does not depend on that assumption. Prior
local suites always supplied the speech helper and did not cover its absence.

## Reproduction and changes

- A new `test-content-initialization.mjs` fixture loads the real required
  helpers/content script with pronunciation deliberately omitted. It reproduced
  the browser exception before the repair and now verifies successful media
  context, dependency-failure retry, duplicate-injection suppression and ready
  PING response.
- Pronunciation is resolved lazily only when its UI needs it. Missing speech
  shows a card-local component/reload message without disabling player
  discovery or cached replay. Later helper loading can be used without capturing
  an earlier undefined reference.
- Content guard version is 21 and is published only after successful setup.
  PING_CONTENT now returns explicit ready/version information.
- Frame inspection errors and message-transport errors are preserved as
  sanitized `Player inspection failed: frame ...` diagnostics. A genuinely
  empty frame remains distinct. Usable video frames still win even when
  unrelated social/ad frames fail.
- Batch lifecycle characterization first failed because the worker discarded
  frame errors; it now covers diagnostic propagation, unrelated failed frames,
  real empty frames and redaction of signed URL query strings.

Saved transcript selection remains after player discovery, so failure to
initialize discovery explains why a saved transcript could not be reached.
The repair does not delete or migrate saved vocabulary/transcript records.
