## Pre-change baseline

- Base commit: `e2acb9d` on `codex/animekai-png-hls`.
- Extension version: 0.10.3.
- The pre-change regression runner passed 12 JavaScript syntax checks, 12
  extension suites, 42 server tests, and Git whitespace validation.
- The user served an authorized local video on `127.0.0.1:8050`.
- The worker rejected the detected source because the public-media SSRF guard
  intentionally rejected all loopback addresses.
- On Chrome's bare media document, the overlay selected `<body>` as the player
  and changed its positioning context, causing the built-in video to disappear.

## Version 0.10.4 changes

- A top-level page on `localhost`, `127.0.0.1`, or `[::1]` may authorize only
  its exact HTTP(S) origin for batch media acquisition.
- The Python worker independently compares scheme, hostname, and effective port
  before allowing the loopback candidate.
- Public pages, embedded credentials, another loopback port, private-network
  hosts, reserved addresses, and unrelated loopback origins remain rejected.
- The authorization is passed only to the current native batch request. It is
  not saved in transcript-library records or technical experiment records.
- A video whose only container is `<body>` or `<html>` receives a fixed
  viewport overlay attached to the document root. The extension no longer
  changes the root page's positioning context.
- Wrapped player containers retain the existing relative-overlay behavior,
  selection, caption dragging, word interaction, and player-control avoidance.

## Required browser check

1. Reload the unpacked extension and then reload the local player page.
2. Serve `player.html` and an MP4 from `http://127.0.0.1:8050`.
3. Choose **Analyze automatically** and confirm the video remains visible.
4. Confirm Diagnostics enters full-video batch preparation rather than showing
   `Private, loopback, and reserved media addresses are not accepted.`
5. Verify the first, middle, and final cues, seeking, cached replay, translation,
   selection, word click, dragging, and TXT/JSON export.
6. Confirm a media URL on another local port is rejected rather than fetched.
