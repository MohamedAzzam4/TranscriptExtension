# 0.12.1 YouTube controls and hover accessibility repair

2026-10-28. WP2.4/WP2.5/WP3.4, baseline cba388a /0.12.0 on
codex/local-media-loopback. Plan: `../YOUTUBE_CONTROLS_FIX_PLAN.md`.

## User evidence and diagnosis

The user reports automatic transcript retrieval works in their browser. Track
type/retrieval route/language and sample URL were not supplied. They also report
a persistent Starting label, an icon that does not reveal settings and hover
pause/settings unavailable. This is real retrieval success plus three reported
UI failures, not a full platform pass.

Source confirms the shared overlay template hardcoded Starting. Audio sessions
replace that text explicitly; YouTube sessions did not, so it stayed after ready.
The settings panel was a child of the native control-button host. This leaves
it vulnerable to overflow/clipping in the button/control ancestry. Its click
listener toggles open locally, but the0.12.0 tests never mounted the actual menu.
Without browser inspection, the exact CSS on the user's page remains unmeasured.

Hover pause defaults off under the approved preference contract. Its switch was
inside Appearance/Transcript, possibly restored collapsed, and the player menu
was inaccessible. Baseline pause-controller tests pass. No independent defect
in the pause algorithm was established; avoid claiming otherwise.

## Repairs

- Overlay starts with an empty, hidden status element. Audio startup still
  explicitly reports recognizer preparation; YouTube progress/source details
  remain in the player menu and popup diagnostics. Critical errors are retained.
- Only the icon stays in the native controls. A separate Shadow DOM panel host
  attaches directly to the player, outside control-button clipping ancestry.
  It stays inside the fullscreen player; player/anchor bounds determine size
  and position. The host passes pointer events through, except on its panel.
- Click, Escape, outside dismissal and inside-panel interactions are handled
  across the two roots. Shared setting changes preserve menu visibility, focus,
  scroll and expanded appearance controls; control replacement recreates one
  icon and one panel. Page cleanup removes both.
- Both shared word switches now live in a non-collapsible **Word interactions**
  section on popup Home, directly after diagnostics. Hover default stays off;
  help explains enabling it. The player panel exposes the same stored settings.
  Retrieval, storage contracts and pause algorithm are unchanged.
