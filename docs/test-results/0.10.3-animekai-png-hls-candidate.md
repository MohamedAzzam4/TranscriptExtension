## Root cause

The CDN does not return a raw transport stream for this AnimeKai path. Each
clear HLS media segment is presented as a tiny valid PNG followed by appended
MPEG-TS bytes. The authorized browser player removes that envelope before
playback. Passing the unmodified response to FFmpeg therefore produces the
correct `Invalid data found when processing input` result.

This is not an HLS language-rendition problem and additional request-header
retries cannot repair it.

## Version 0.10.3 changes

- Detect the wrapper only after a normal HLS decode fails with invalid input.
- Require an ordinary unencrypted media playlist.
- Inspect only the first segment and accept the special path only when:

  - the response is a PNG;
  - its chunk structure reaches `IEND`;
  - bytes remain after the PNG; and
  - at least three aligned 188-byte MPEG-TS packets are present.

- Stream wrapped segments sequentially, discard the PNG envelope, decode AAC
  audio from in-memory MPEG-TS, resample to mono 16 kHz, and discard each
  compressed segment immediately.
- Bound segment count, individual payload size, and total streamed bytes.
- Show `HLS segment transport` in visible diagnostics and retain only wrapper
  kind plus segment count in technical exports.
- Keep signed playlists, segment URLs, media bytes, cookies, authorization,
  DRM material, and PCM out of persistent records.
- Move legacy Performance-resource classification to a deterministic,
  pathname-only helper so `ping.gif?event=playlist` is not a media candidate.
- Bump the content-script generation so an extension reload can replace the
  previous collector on an already-open page.
