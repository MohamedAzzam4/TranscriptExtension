## Behavior

- Static isolated/MAIN YouTube adapters discover the current video and its
  caption tracks. Auto-select prefers creator-provided subtitles in the selected
  spoken language, then original automatic captions. Translated-track URLs
  cannot be accepted as source speech. Track choice is per current video.
- Retrieval starts on opening a video or SPA/playlist navigation, when globally
  enabled (default on). The controller polls navigation/control replacement at
  800 ms and probes reported audio-language changes at 3 seconds. Page metadata is
  bounded and validated; private player objects do not enter storage.
- Browser text-only requests have 18-second deadlines and 8 MB response limits.
  Failed browser discovery/retrieval tries the existing native transport with an
  explicit captionsOnly flag. The Python branch uses yt-dlp metadata/caption
  extraction only, before source resolution/audio acquisition/load_model.
  45-second helper deadline/cancellation. No native executable change is required:
  the existing batch command transports the new Python branch.
- Missing/unusable captions show a warning/retry. Audio ASR is an explicit mode
  or player action; it is never started by failed caption retrieval. Generic
  audio/live/embedded-player paths remain available. Switching modes stops an
  audio experiment in the same tab, without replacing other tabs' audio sessions.
- One transcript button is added to the desktop player's right controls. Its
  isolated panel offers enable/retry/track/language/translation, independent
  font/size/color/bold controls and background appearance, plus explicit audio
  mode. Escape/outside closes it; menu focus/scroll/disclosure state survives
  setting changes; dimensions are bounded by the player. Controls are reattached
  after replacement. No changes to YouTube's own settings menu.
- Native caption visibility is suppressed only while the extension owns an
  overlay, restored on stop/off/navigation/pagehide and allowed during ads.
  Our overlay is suspended during detected ads. Native caption preferences are
  not changed or saved by this feature.
- YouTube target translation is requested separately when supported, aligned by
  overlapping time windows and labelled as a translation. Missing target data
  falls back to the existing Chrome/configured Google provider. Source survives
  target failure. Source/target tracks are cached; two target languages are
  retained per source record. Word-card translations retain their own existing
  provider contract rather than becoming YouTube dictionary translations.
- Caption sessions use captionSegments, transcriptSource.sourceVersion 1 and
  captionsUsedAsInput:true. asrSegments/audioCoverage stay empty; evaluation is
  not-applicable. TXT/JSON/library and diagnostics carry source provenance.
  Caption cache identity includes video, language, track ID and track kind,
  separate from old ASR records. Cached reuse does not create duplicate caption
  experiments. Library saves are serialized across concurrent tabs; a failed
  write does not first evict older records. Cache failure leaves usable captions
  in the tab with an explicit unsaved warning.
- Requests are scoped to video/document/generation. Stale responses and late
  cancellation cannot replace a new video. Stop/off/navigation cancel in-flight
  browser/native requests. Diagnostics updates serialize to retain source,
  timing, pronunciation and card information alongside status updates.
- Caption text is normalized/deduplicated while retaining cue timestamps.
  Available individual JSON3 word-segment offsets retain platform provenance;
  within-cue interpolation is estimated, never reported as recognizer timing.
- Shared captionPreferences add highlightCurrentWord (default true) and
  pauseOnWordHover (default false). Popup and player edit the same browser-local
  settings; existing sessions observe changes. Saved-word marking, selection and
  dictionary activation are independent of the moving-word highlight switch.
- Hover pause owns only playback it paused. Already-paused media stays paused;
  adjacent words do not briefly resume; manual pause/play intent relinquishes
  ownership. Leaving/disabling restores owned playback; navigation does not
  start an old video. No lookup/network request is caused by hovering.
- Saved vocabulary from caption sessions retains the video's source reference
  explicitly. Word cards, YouGlish, source return, replay, selection, dragging
  and appearance controls keep their existing implementations.

## Acceptance boundary and limitations

Candidate: **Experimental**. Full milestone status: **Needs development** until
the required real-browser matrix passes. Browser testing remains paused by the
user's earlier restriction. Passing doubles do not prove live captions are
available, that the browser/local helper succeeds against YouTube, or that the
button renders in normal/theater/fullscreen/zoom and real mouse/keyboard usage.

YouTube's player metadata/control DOM and caption endpoints are unofficial and
can change. Requests that fail from access restrictions/rate limits/player
changes are reported; no access-control bypass or cookies exported to the helper.
The local helper must use this updated Python source; browser-first retrieval
does not require it when successful. Signed caption URLs remain memory-only.

Live streams are explicitly unsupported by this full-track mode. Desktop watch
pages are the intended first acceptance target. Shorts, mobile layouts, dubbed
track discovery and recordings of prior live streams require real acceptance
samples. Player-reported audio language is used when present; otherwise the
user's configured spoken language is used. Matching language is not a proof
that creator text exactly matches the dub; no such claim is made.

Cache checks do not discover creator edits automatically. A cache's source
version is validated; future revision/freshness policy needs measured samples.
Native fallback uses JSON3; unsupported formats fail explicitly. Caption source
and translations are bounded by the existing 7.5 MB video-history cache budget.
Old data has local compatibility coverage, but no same-folder installed upgrade
test was run. Existing dictionary corpus failures remain unchanged.
