# Analysis startup storage quota repair

Date: 2026-10-25. Version 0.11.0 working-tree candidate, branch
`codex/local-media-loopback`, baseline commit `0455ce3` plus existing changes.
Parent implementation only. WPs WP1.3 / WP0.3 / WP2.4; dependencies are the
existing analysis/cached-replay persistence, local/session storage and popup
diagnostics. Protected contracts: saved vocabulary/transcripts, acquisition,
cached replay, diagnostics and user preferences.

## Report and diagnosis boundary

The user clarified that video analysis, previously failing at discovery, now
reports `Resource::kQuotaBytes quota exceeded`. Chromium's storage quota
enforcer generates this message for total storage quota overflow. This is a
different failure class from missing HTML video discovery. Source inspection
found the extension still used the standard local storage cap while storing
transcript library records, repeated experiment records, and translation/
dictionary caches together. Cached replay also writes a new experiment record.

Current Chrome storage documentation was retrieved via Context7:
[local/session quotas and unlimitedStorage](https://developer.chrome.com/docs/extensions/reference/api/storage).
The standard local cap is 10 MiB; `unlimitedStorage` lifts this local cap,
but does not remove session-storage or physical-disk limits.

Read-only regular-page console inspection did not capture the current quota
exception. Browser policy rejected access to the privileged extension-management
URL; no alternate surface, profile/database access or workaround was attempted.
Therefore exact live byte usage, responsible key and failing write were not
measured. Local capacity is a source-supported explanation, not a claim that
live storage metrics were obtained. No user browser data was deleted or changed.

## Repairs

- Add `unlimitedStorage` for full transcript/experiment persistence, preserving
  stored records rather than clearing data. No new host access is requested.
  Manifest changes need extension reload before affecting the running instance.
- Move popup settings persistence inside the analysis action's try/finally.
  Quota failure is displayed and releases Analyze, rather than escaping the
  handler and leaving the action disabled. A characterization fixture reproduced
  the prior unhandled rejection before source repair.
- Catch analysis startup failures after media discovery as well as preparation
  failures. Store lightweight failure diagnostics in session storage instead
  of falsely showing the last successful analysis.
- Classify experiment-save quota errors explicitly as local analysis-storage
  failures. No deletion, eviction, success claim, schema migration or hidden
  fallback is performed. Attempt to retain the failure in session diagnostics
  without overwriting the original exception if diagnostics themselves fail.
- Add sanitized Local storage usage to diagnostics via getBytesInUse, with
  actual running-manifest quota policy. Usage-inspection failure does not block
  saved data reads or normal diagnostics.

## Evidence and limitations

all 18 extension suites, all 46 server tests and whitespace checks pass.
Server tests used workspace TEMP/TMP as previously recorded.

New/expanded fixtures cover settings-save failure/button recovery, the manifest
capacity contract, explicit experiment-save quota classification, preserved

diagnostics and usage above the former 10 MiB cap. The permission's real effect

reload or user-data cleanup was performed. Real quota recovery after reloading
the extension remains unverified. Existing library retention limits remain
unchanged. Experiment/cache growth may still need a later user-visible history
management policy; unlimitedStorage does not mean infinite disk capacity.

Classification: **local regression Pass; real browser/storage acceptance
