# Browser German pronunciation candidate

Date: 2026-10-25. Version 0.11.0, branch `codex/local-media-loopback`,
baseline commit `0455ce3` with the existing uncommitted candidate.
Implemented directly by the parent agent; Terra delegation remains stopped.

WP1.3 / WP2.4 / WP2.5: replace local-only extension TTS with the user's
German-cards site's browser Web Speech approach. Dependencies are the existing
content-script injection, speaker gesture and card/session ownership. Protected
contracts: player discovery, cached replay, selection/copy, word lookup/save,
YouGlish, video replay/restoration, outside dismissal and embedded-player support.
Status: **Experimental: automated regression passes; actual browser speech
and platform acceptance remain unverified.**

## Source decision and implementation

The user supplied
[German-cards source](https://github.com/MohamedAzzam4/German-cards-temp/blob/main/index.html#L1561-L1627)
and explicitly approved its approach. Current Web Speech voice/event/error
documentation was retrieved via Context7 from MDN. This supersedes earlier
local-only voice contracts and Windows-installation guidance.

- Added `extension/german-pronunciation.js`, loaded before `content.js` in
  each injected application frame. It selects only an explicitly German
  browser voice, preferring `de-DE` and accepting another German variant.
- Uses `speechSynthesis` and `SpeechSynthesisUtterance` synchronously from the
  speaker click, preserving user activation. Rate is 0.92 and pitch is 1,
  matching the reference site. The utterance language follows the selected
  German voice. It never speaks through an English/default fallback.
- Accepts local and online voices. Card availability and speaking feedback
  identify which type is selected; browser-provided online speech can send the
  selected word to the browser's speech service. No API key/provider SDK added.
- Listens for `voiceschanged`; late German voice availability updates the card
  without automatically starting audio. Missing voices remain blocked with
  Check again and browser/system guidance, without requiring a Windows voice
  when the browser already provides a suitable one.
- Acceptance, actual start/end, cancellation/interruption, engine/network/
  browser-policy errors and unconfirmed timeouts remain distinct. Closing the
  card, changing words or ending the session cancels owned speech; late events
  cannot repaint a newer request. Word replay continues through its separate
  reversible video playback path.
- Removed the old worker `chrome.tts` handlers and `tts` permission. Bumped
  the content-script guard to 20. Updated injection and syntax-runner contracts.

## Baseline and evidence

Before source changes, content syntax, the overlay suite and batch lifecycle
suite passed. A new behavior fixture was authored before the implementation
and initially failed because the pronunciation module did not yet exist.

After implementation, the complete local regression runner passed:

- all 14 extension JavaScript entry/helper syntax checks;
- all 16 extension test suites, including the new browser pronunciation suite;
- all 46 server unit tests;
- `git diff --check` (line-ending notices only).

The new suite exercises missing/English-only voices, delayed voice arrival,
online de-DE preference, alternate German variants, utterance properties,
acceptance versus actual playback, terminal errors, stale callbacks,
cancellation and start/completion timeouts. Existing initialization,
cache/discovery, vocabulary, grammar and caption suites also pass.
Server tests used workspace TEMP/TMP to avoid the previously recorded sandbox
temporary-directory permissions issue. No new environment/dependency installed.
