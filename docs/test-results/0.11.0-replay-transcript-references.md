# Cached replay transcript references

Date: 2026-10-25. Baseline: `0455ce3`, branch
`codex/local-media-loopback`, with pre-existing uncommitted 0.11.0 changes.
Scope: user's specific request to stop persisting another complete transcript
inside every cached-playback experiment. No parent-task work is delegated.

WP3.5 bounded storage correction, using the existing complete-library contract
from WP3.3. Protected contracts: TR-CACHE, TR-EXPORT, TR-SEEK, diagnostics,
appearance/sync persistence and library removal. This does not start the broader
folder-history or retranscription roadmap work.

## Baseline and intended contract

Before editing, batch lifecycle, coverage and learning suites pass. Source and
historical `1546662` show cached replay constructing a new experiment with the
entire saved transcript, then saving it permanently. The active baseline test
even expects 250 duplicate segments in the replay experiment.

New replay experiment records will persist a small explicit versioned reference
to the existing canonical library entry and its original source experiment,
without segment payloads. Runtime reads resolve that reference for playback,
exports and diagnostics. Metadata saves must not put hydrated segments back.
Use source identity/version information to avoid returning a later replacement
transcript. If the library is removed/evicted, the already-existing original
analysis supplies the segments. If neither remains, fail explicitly rather
than display a successful empty transcript. Existing inline historical records
remain readable, without an automatic migration or deletion.

## Required evidence

Characterize before implementing: repeated replay creates no segment payloads,
actual content messages and TXT/JSON exports retain cues/timings, metadata
updates/stop preserve compact storage, original/library records stay unchanged,
library removal/replacement resolves the correct original version, missing or
cyclic references fail honestly, and old inline experiments remain readable.
Run the full local regression runner after repair. An isolated synthetic browser
check may validate the persistent wire contract without a personal profile or
live services. Real video/player acceptance remains separate.

## Implemented contract

`startLibraryExperiment` now creates a `transcriptReference` with schema version,
library key, stable identity, original source experiment ID and a deterministic
content fingerprint. The runtime still receives all normalized cues/word timings.
`saveExperiment` checks the reference, persists an empty `asrSegments` array and
keeps runtime hydration separate from storage. Sync/appearance updates and Stop
use the same persistence boundary. Small new playback metadata records remain;
settings/translation writes were outside this request and remain unchanged.

`getExperiment` resolves the saved library version, with the already-existing
original analysis as fallback. Replacement content cannot silently become an
older replay's transcript. Invalid, missing or cyclic references produce explicit
errors. Existing inline historical experiments remain readable. No user's
historical copies were migrated, deleted or compacted by this update.
